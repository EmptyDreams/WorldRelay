# WorldRelay · 世界接力

**朋友轮流当房主，同一个世界接着玩。**

不用为了偶尔联机专门养一台能跑 MC 的高配服务器，也不用在上线前先问一句「有没有人开服了」。

WorldRelay 让同一个 Minecraft 世界在你们之间自动接力：**谁想玩，谁就开；有人在玩，直接进；玩完自动把最新进度交出去。**

## 适合谁？

**适合**
- 2～5 人的固定小圈子。
- 服主手上正好有一台带宽足够的服务器：CPU、内存、硬盘速度要求都很低，钱主要花在带宽和硬盘容量上。

**不太适合**
- 想十几个人同时在线：房主家宽的上行要同时喂给所有人，会先卡住房主。
- 中继服务器是带宽紧张的小水管：上传、下载存档会等到怀疑人生。

## 你是不是遇到过

- 每次联机前都要确认「最新存档在谁那儿」，传错一次白玩一晚上。
- 有人开了 LAN，其他人却连不上；想联机得先研究内网穿透或者虚拟局域网。
- 为了偶尔一起玩租了高配服务器，结果大部分时间没人上线，白浪费钱。
- 换人开服之后，地图、路标、蓝图、收藏全丢，像换了个新世界。

WorldRelay 把这四件事交给程序：**最新进度永远只有一份，托管权同一时间只属于一个人，自动处理模组自定义的数据，交接自动完成。**

## 它能带来什么

| 你想要的 | WorldRelay 的做法 |
| --- | --- |
| 不想再管存档 | 进世界前自动同步最新进度，退出后自动上传；中断可重试 |
| 不想约时间开服 | 有人托管就加入，没人托管就自动成为房主 |
| 不怕两个人同时开 | 同一时刻只有一个人能托管，进度不会被两份存档互相覆盖 |
| 不怕崩 | 没上传的进度留在本机，重进即可继续；实在救不回来还能回滚历史备份 |
| 换人不丢个人数据 | 地图、路标、机械动力蓝图、收藏、物品栏配置都跟着世界走，不随房主变 |
| 不想学运维 | SSH 里一个终端界面就能看状态、建号、建世界、恢复备份 |

## 开始之前：环境与带宽

**环境要求**

| 角色 | 要求 |
| --- | --- |
| 游戏 | Minecraft 1.21.1 + NeoForge |
| 玩家 | 所有人安装模组（非 windows_x64 环境需自行安装 rsync） |
| 服务端 | Linux x64 / ARM64；原生版不需要 Java，JAR 版需要 Java 21+，依赖 `rrsync` |
| 网络 | 一台公网可达的小服务器；推荐使用其它工具提供 HTTPS |

### 没有现成服务器？先算一笔账

WorldRelay 不是「租服务器开服」的替代品。它最适合的场景是：

> **手上已经有一台带宽充裕的小服务器，但 CPU、内存或磁盘速度偏弱，直接跑 Minecraft 服务端会很吃力。**

这种机器用来当中继正好：计算压力几乎为零，瓶颈只在带宽，而带宽恰好是它最富裕的资源，比再买一台能跑 MC 的机器省钱得多。

如果你是为了 WorldRelay 专门买服务器，或想要追求最佳的游戏体验，建议先把两条路线摆在一起比较：

| 路线 | 体验 | 成本主要花在 | 适合 |
| --- | --- | --- | --- |
| 传统开服 | 最好：24 小时在线，兼容性极佳，不存在交接 | CPU、内存、磁盘容量与性能 | 人数多、追求游戏体验、不想等交接 |
| WorldRelay | 部分模组有兼容问题，交接要等 | 带宽、磁盘容量 | 已有便宜的大带宽机器且人数较少 |

判断方法很简单：**把「高带宽中继」和「能跑 MC 的高配机器」的月费摆在一起算**。如果省下来的钱不足以抵消「房主不在就玩不了 + 每次交接要等」这两个体验损失，那直接租一台 Minecraft 服务器更划算。

世界接力真正的价值是**复用你已经有的机器**，而不是让你为了它专门升级硬件。

## 三步开始

> 前提：管理员已经部署好服务器，并给了你接口地址和 Token。

1. **装模组**：把 WorldRelay 的 JAR 放进游戏目录的 `mods/`（所有玩家都要装）。
2. **填设置**：主菜单点「共享世界」→「设置」，填好连接信息并保存。
3. **进世界**：在共享世界列表里选世界，剩下的自动完成。

连接设置怎么填：

| 设置 | 怎么填 |
| --- | --- |
| 协议 | 首选 HTTPS；服务器没启用 TLS 时选 HTTP |
| 接口地址 | 管理员给的域名，不带端口和路径，例如 `relay.example.com` |
| 接口端口 | 通常是 `443` |
| 服务器 Token | 管理员分配给你的 Token |
| 同步工具 | 使用内置、自动查找已安装、自定义路径看情况选，一般默认即可 |

**Token 相当于密码，别发给别人；泄露了找管理员重置。**

## 进入世界后会发生什么

| 世界当前情况 | 你会看到 |
| --- | --- |
| 还没有存档 | 成为房主，进入原版「创建新世界」流程 |
| 空闲、已有存档 | 自动同步最新进度，在本机启动世界 |
| 房主正在玩 | 直接连上去，和你平时进朋友的世界一样 |
| 正在上传 / 等待恢复 | 显示当前进度，完成后再进入 |

## 房主交接小抄

当房主只有三件事要记：

1. **正常退出世界，等「上传完成」再关游戏。** 上传没完成就退出，世界会卡在「等待原房主恢复」，大家都进不去。
2. **别删游戏目录里的 `worldrelay/`**。
3. **崩了也别慌**：重开游戏、重进同一个世界，按提示继续托管即可；实在恢复不了，找管理员回滚备份。

另：房主的上行带宽会直接影响其他人卡不卡。上行很小的话，建议减少同时在线人数或调低视野。

### 存档太大、下载太慢怎么办

如果存档已经特别大了，走服务器下载要的时间太长，可以通过其它速度更快的途径先下载一份存档，不是最新的也没事，本地有了存档后增量传输的压力就会小很多。

在共享世界列表中选中目标世界，点击右侧的**「导入存档」**，选择 ZIP 压缩包或包含 `level.dat` 的已解压文件夹，也可以直接拖入。ZIP 中的文件可以直接位于根目录，或统一放在一层存档目录中。

导入只准备本地增量缓存，不会直接替换服务器存档，也不需要先成为房主。之后进入该世界时，客户端会补齐差异、校验到服务器最新版本后再打开世界。每个世界只保留一份最新缓存，导入失败会保留原有数据。

右侧的**「删除本地存档」**会清除当前服务器、当前账号下该世界的全部 WorldRelay 本地数据，包括工作存档、缓存、上传副本和恢复记录。有未上传进度时会额外警告并要求确认；服务器存档不会删除，托管资格也不会自动释放。正在运行或同步时不能删除。

**「导出存档」**可以将本地存档保存为 ZIP，再分享给其他玩家导入。优先导出已停止的工作存档（包含未上传进度），没有工作存档时使用完整缓存；正在运行或同步时不能导出，覆盖已有文件前会要求确认。

## 兼容模组

WorldRelay 已对部分模组做了兼容处理，在交接房主后这些模组的数据不会出现问题。

| 模组 | 换房主后保留什么 |
| --- | --- |
| 机械动力 | 已上传到服务器的蓝图不会因为换了房主而丢失 |
| Xaero 世界地图 / 小地图 | 个人地图和路标继续沿用，不会因为换了房主就丢掉 |
| Inventory Profiles Next | 个人物品栏配置、锁定槽位、村民书签 |
| JEI | 个人收藏和查询历史 |

不在列表中的模组，如果涉及世界存档的读写，可能会出现兼容性问题。

判断是否兼容——如果一个模组存在以下任意一种情况，不专门做适配就是不兼容的：

- 模组会在世界存档之外的目录存储数据（如机械动力玩家上传的蓝图不会保存在存档目录）；
- 模组在 LAN 模式下房主与玩家的存储数据的格式、位置不一致（如 Xaero 系列）；
- 模组将房主个人数据直接记录在存档目录中且不区分玩家身份。

不兼容的游戏表现可能有：

- 切换房主后部分数据丢失及其衍生问题；
- 切换房主后玩家数据发生漂移（本来是玩家 A 的数据变成了玩家 B 的）。

## 常见问题

1. **两个人能同时各开一份吗？**
    不能。托管权是排他的，一个存档同一时刻只有一个人能对外托管。
2. **支持离线账号吗？**
    支持，建世界时选择「允许离线账号」。此时所有人统一用离线身份，玩家数据按玩家名区分，请保持名字不变；该模式创建后不可修改。
3. **房主必须一直开着电脑吗？**
    是，世界跑在房主电脑上。房主退出后，其他人要等交接完成才能进。
4. **为什么不用 P2P 直连？**
    因为需要一份权威存档和唯一的托管者。中继同时负责存档和仲裁，直连做不到。
5. **需要多大的服务器？**
    CPU 和内存要求很低，但带宽是硬门槛：它同时承载游戏流量和存档传输，带宽越大传输存档速度越快。

# WorldRelay 管理终端

在服务器的 SSH 终端中运行，首页直接展示服务概览。通过本机管理 HTTP 接口管理世界、备份和用户。
发布程序是独立的 Linux 静态可执行文件，运行时无需 Go、Python、curl、jq 或额外终端组件。

## 运行

将对应架构的 `worldrelay-admin` 放进服务目录下的 `admin/`，赋予执行权限：

```bash
chmod +x ./admin/worldrelay-admin
./admin/worldrelay-admin --port 2001
```

端口必须与服务端 `registration.port` 一致，默认 8081；开发机使用 2001。

首页按运行信息、联机情况、后台任务、磁盘、CPU、内存和网络分组展示。三栏时 CPU 位于第二行左侧、
内存位于第三行左侧，各占两栏；磁盘、网络分别位于右侧。CPU 和内存进度条用绿色、橙色、灰色
分别表示本进程、系统其余占用、空闲，前两项合计为系统总占用；无颜色终端仍可通过符号区分。
普通终端使用两栏，较窄窗口改为单栏，各卡片占一栏并隐藏进度条。
磁盘、网络内容按固定行距从顶部排列，卡片补齐的空白放在底部。
内容较长时将鼠标放在内容区，用鼠标滚轮滚动；只在需要滚动时显示提示。
后台任务条目均匀占用卡片高度。首页入口集中在底部菜单，通过方向键或 WASD 移动光标，回车进入；
默认选中世界管理，另有用户管理、退出和待确认操作；首页默认每 5 秒后台刷新。
首页没有上一级，因此不显示 ESC 返回提示。
导航、内容、状态和快捷操作分别分区，列表通过列分隔线与选择标记对齐。
世界管理左侧只显示世界名称与当前状态，选择后右侧自动展示详情、分类存储占用及备份列表。
右侧滚轮独立滚动；空格切换列表与详情焦点，窄窗口按焦点显示其中一栏。
确认页独立显示操作影响、目标世界及备份版本。所有页面正常时隐藏状态标记，仅在异常时显示原因。
首页正常时不显示状态条，接口异常时在服务概览内显示原因；恢复连接后自动清除。

世界行显示总世界数和有持有者的世界数，离线待恢复的持有者也计入后者。
用户行显示注册用户总数，以及仍通过隧道连接的启用账号数，房主和已配对访客按用户名去重。
只查询 API、持有未使用票据和未认证的连接不计入在线人数。
存档磁盘与传输磁盘分别是世界目录、传输临时目录所在文件系统的可用与总空间；同盘时数值相同。
堆已使用是当前堆占用；JVM 下的堆已分配是当前堆容量，包含空闲部分。
Native Image 下展示堆已使用和堆上限，不将 `Runtime.totalMemory()` 当作已分配容量；这些数值均不代表进程 RSS。
CPU 显示系统与进程使用率、总核数与进程可用核数、1 分钟负载；进程 CPU 以整个系统的逻辑核心总量归一化。
内存同时展示系统已用内存和协调服务进程 RSS。网卡速率与累计流量汇总非回环接口，属于系统流量。
Linux 指标读取 `/proc`，最多每秒采样一次，不启动外部命令；首次 CPU／网络速率与不可读指标显示“—”。

工具固定访问 `http://127.0.0.1:<端口>/api/v1/`，不经过环境代理，不跟随 HTTP 重定向。
使用普通有伪终端的 SSH 会话（远程直接执行时用 `ssh -t`），建议 UTF-8 终端、至少 80 列 × 24 行。
较小终端支持滚轮和翻页；确认预览滚动时输入框始终显示。启用鼠标的终端通常可用 Shift 加拖动选择文字。
服务端必须包含 [日常管理接口](../server/README.md#日常管理接口)；404 会显示接口或记录缺失，不尝试修改 nginx 或域名解析。

```bash
./admin/worldrelay-admin --port 2001 --refresh 5s --timeout 10s
# 只读检查接口，不启动全屏界面，也不创建操作目录：
./admin/worldrelay-admin --port 2001 --check
./admin/worldrelay-admin --version
```

## 按键

所有操作均可通过键盘完成。终端本身的粘贴快捷键可用于输入名称及原因。
表单使用真实终端光标，并随中文宽度和横向滚动定位，让本地拼音输入法的候选窗跟随输入框。

| 页面 | 按键和用途 |
|------|------------|
| 首页 | `←→` / `AD` 移动底部菜单焦点，`Enter` 选择；内容较长时用鼠标滚轮滚动 |
| 世界列表 | `↑↓` 选择世界，`←→` / `AD` 切换创建、刷新、改名按钮，`Enter` 选择，空格切到详情；`Esc` 返回首页 |
| 世界详情 | 空格进入时默认选择刷新；按钮依次为刷新、恢复备份、删除备份、放弃进度、删除世界；`↑↓` 选择备份，`←→` / `AD` 切换按钮，`Enter` 执行，滚轮滚动详情 |
| 其他页面 | `←→` / `AD` 选择底部按钮，`Enter` 执行，`Esc` 返回；所有内容滚动统一使用鼠标滚轮，`Ctrl+C` 退出 |
| 用户列表 | `↑↓` 选择用户，通过底部按钮创建、启用／禁用、重置 Token 或刷新；状态变更和重置均需输入目标名称确认 |
| 表单与确认 | 保持输入框焦点，方向键编辑文字，`Enter` 提交或确认，`Esc` 取消，不显示操作按钮 |
| Token 结果 | 通过底部按钮显示／隐藏 Token，或返回用户列表；离开页面后清除，不保存到文件或操作记录 |
| 待确认操作 | 选择重试按钮复用原请求；可返回首页查询，再通过待确认操作入口继续 |

首页和用户列表默认每 5 秒刷新；`--refresh 0` 关闭。世界列表仅在进入页面或选择刷新按钮时重新获取，选择世界时读取该世界的详情。
世界页底部仅保留本页操作，页面返回使用 `Esc`。请求在后台执行，写入过程中阻止重复提交。
用户列表的“传输授权”列为服务端当前记录的临时 rsync/SSH 传输凭据数量，不表示用户权限等级或正在传输的连接数。
没有当前持有者时，“放弃进度”置灰，方向键跳过该按钮；有持有者的离线待恢复世界仍可显式放弃。
世界和账户的最终约束由服务端执行：禁用用户不释放所有权，恢复不回退版本号，世界及历史备份删除要求世界空闲。
当前权威快照不能删除。上一持有者取自仍保留的托管／放弃记录，不将管理恢复操作算作玩家托管。
恢复备份会发布递增的新版本；“当前”标记对应新版本，同时显示“恢复自 #来源版本”。改名成功后直接回到世界列表。
存储占用统计文件逻辑字节数，分为权威快照、历史备份、临时副本、传输目录及元数据；不可读取时显示“—”。
时间按运行工具的服务器本地时区显示。堆统计不等于 RSS，位于同一文件系统的空间不能相加。

## 中断与重试

恢复、删除和放弃进度均先获取服务端预览，再展示目标、任期、版本及影响，输入完整名称确认后才发送。
确认请求会先以原操作编号和完整字段原子保存到可执行文件旁的 `state/pending.json`。
记录包含管理操作参数，不包含 API Token 或 SSH 私钥；目录权限 0700、记录 0600。
同一操作目录通过内核文件锁限制为一个交互终端，退出或崩溃后自动释放。
可用 `--state-dir <目录>` 改位置；保持默认即可集中清理所有文件。

- 恢复返回 202 时每秒查询同一个请求，成功后清除记录。
- 网络中断或服务端 5xx 时保留记录，选择重试按钮复用原请求；退出后再次启动仍可继续。
- 重启工具后不会自动执行上次操作，需要选择重试按钮查询；存在待确认记录时阻止发起其他写操作。
- 服务端返回明确的 4xx 拒绝时清除记录，按错误提示刷新并重新预览。
- 创建账户／世界和重置 Token 不自动重试。未收到响应时先返回列表核实；丢失 Token 时显式重置。

关闭管理终端不会停止服务端，也不会取消已开始的恢复任务。不要删除仍有待确认操作的目录；
手工清理记录不会撤销服务端已经执行的操作。服务端的幂等回执与删除回收副本都有保留窗口，建议及时核实结果。

## 构建与验证

开发需要 Go 1.26 或更新版本，发布程序无需编译器。依赖由 `go.mod` 与 `go.sum` 锁定：

```bash
cd admin
go mod download
go test -race ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o build/linux-x64/worldrelay-admin .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags='-s -w' -o build/linux-arm64/worldrelay-admin .
# 在 Linux 开发环境验证真实终端输入输出（仅该测试需要 Python 3）：
python3 -B terminal-smoke.py build/linux-x64/worldrelay-admin
```

交互和 HTTP 测试使用隔离的假服务。另有真实 Java 服务集成测试，显式设置 JAR 后执行：

```bash
WORLDRELAY_TEST_JAR=/absolute/path/server-0.1.0-SNAPSHOT.jar \
WORLDRELAY_TEST_JAVA=/path/to/java21/bin/java \
go test -race -count=1 -run TestRealServerManagement -v .
```

该测试自行启动随机端口的独立服务，账户、合成存档和全部操作都在测试临时目录中，结束后关闭并清理。
覆盖创建与改名、两版提交、备份恢复、历史、用户禁用／启用、保留所有权、放弃及删除。
合成存档只验证管理与发布协议，不启动 Minecraft，也不验证真实游戏数据语义。
开发机测试时将 `GOCACHE`、`GOMODCACHE`、`GOPATH`、`GOTMPDIR`、`TMPDIR` 和 `XDG_CONFIG_HOME`
全部设在同一 `admin/` 工作目录下；最后一项也将 Go 工具自动生成的构建计数文件集中到该目录。

GitHub Actions 的 **Admin Console** 工作流运行测试及静态检查，并产出 Linux x64、ARM64 两个压缩包与 SHA-256。
支持手动触发及相关源码变更触发；目前上传为 Actions 产物，不创建 Release。
